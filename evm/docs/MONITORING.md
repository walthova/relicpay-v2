# RelicPay v2: Monitoring and Alerting Plan

Status: tooling shipped, hosting not wired. Everything here runs offline against any RPC. What is missing is a place to run it on a schedule and a channel to deliver pages, both of which need owner decisions (section 8).

Machine readable companion: `monitoring/alerts.json`, generated by `tools/monitor.js` (`npm run monitor:catalog`, `npm run monitor:check`). It lists every event of every in-scope contract with its severity and a one line reason. The check fails if a contract gains an event with no rule, so the plan cannot fall behind the code.

## 1. What we are protecting against

Ranked by what hurts most, using the trust model in `docs/AUDIT_PREP.md`.

1. Authority moving without anyone deciding it should. Ownership, the governor role, the oracle pusher set, the governance allowlist. These gate every privileged setter, so a quiet change here is the start of most real incidents.
2. A bad or dead price. With an oracle wired, a stale ETH price blocks credit-line refreshes for any buyer holding ERC20 collateral, which includes payment completion and `triggerDefault` (ADR-009). A wrong price mis-values collateral for everyone.
3. Funds leaving unusually. Large seller withdrawals, collateral seizure, defaults.
4. Governance acting. A parameter change executing against a live target, or the timelock being shortened.
5. A keeper that quietly stopped. Nothing reverts when nobody pushes a price, so only a state check can see it.

## 2. Two kinds of signal

Events say something happened. They are cheap, ordered and complete, so most of the plan is events: `scan` decodes logs for a block range and returns alerts.

State checks say something is true now. A stale oracle emits nothing, and an owner that was changed a week ago is not in this hour's logs. `health` reads the contracts directly and returns findings.

Run both. Events are the audit trail, state checks are the dead man's switch.

## 3. Severities and routing

| Severity | Meaning | Delivery | Response target |
|---|---|---|---|
| page | Funds at risk, authority changed, or a safety net is down | Push notification to the owner on call plus email | Look within 15 minutes, act within the hour |
| warn | Unusual but the protocol is behaving as designed | Daily digest email | Review within one working day |
| info | Dashboard and audit trail only | Stored, never delivered | None |

Page volume must stay low enough that a page is believed. If a page rule fires on normal operation, move it to warn rather than learning to ignore it.

## 4. The page tier

These events always page. The authoritative list is `monitoring/alerts.json`; this table is the human summary and a test keeps it complete.

| Event | Contract | Why it pages |
|---|---|---|
| OwnershipTransferred | Every Ownable contract | Owner controls the privileged setters. RelicPay's agreement level OwnershipTransferred (NFT to buyer) is info |
| GovernorUpdated | RelicPay, PriceOracle, DeFiIntegration | Governor can call every onlyGovernance setter |
| PriceOracleUpdated | RelicPay | A swapped oracle misprices every ERC20 position |
| OracleAuthorized | PriceOracle | A new address may push prices |
| AssetRemoved | PriceOracle | Positions in that asset can no longer be valued |
| FeedRegistered | ChainlinkPriceAdapter | A wrong feed misprices the asset |
| SequencerFeedSet | ChainlinkPriceAdapter | The L2 sequencer uptime feed or grace period changed; disabling it removes the stale-price guard after a restart |
| ProposalExecuted | RelicPayGovernance | A governed change hit a live target |
| TimelockParametersUpdated | RelicPayGovernance | A shorter delay removes the cancel window |
| ActionAllowanceUpdated | RelicPayGovernance | The allowlist bounds what governance can call |

Two numeric rules escalate an otherwise quiet event to a page. Both thresholds are in `monitoring/alerts.json` under `thresholds` and are overridable per call.

| Rule | Default | Raises |
|---|---|---|
| Large seller withdrawal | 50 ETH in one SellerWithdrawal | SellerWithdrawal from info to page |
| Price deviation | 2000 bps between consecutive pushes of the same asset | PriceUpdated from info to page |

Both defaults are placeholders. Set them from real pilot volumes before mainnet; the first month on Sepolia will show what normal looks like.

## 5. The warn tier

Reviewed daily, not paged: defaults and seizures (`AgreementDefaulted`, `CollateralSeized`), timelock activity (`ProposalQueued`, `ProposalCanceled`, `ParameterUpdated`), configuration drift (`GovernanceUpdated`, `MaxAgreementDurationUpdated`, `SettlementTokenAuthorized`), issuer changes (`IssuerSet`), oracle housekeeping (`AssetAdded`, `OracleDeauthorized`, `MaxPriceAgeUpdated`, `FeedRemoved`) and DeFi protocol changes. `PushSkipped` is warn per event, but a run of them for one asset means the Chainlink feed is unhealthy and should be treated as a page by whoever sees it.

`ProposalQueued` is the one to read carefully. It is the only time a bad governance action can be stopped, because the owner can cancel during the delay.

## 6. State checks

`health` returns findings. A page finding makes the CLI exit non-zero, which is what a scheduler should alert on.

| Check | Severity | Condition |
|---|---|---|
| ORACLE_UNWIRED | info | RelicPay has no oracle (legacy valuation mode, ADR-009) |
| ORACLE_STALE_SOON | warn | ETH price older than 80 percent of its max age |
| ORACLE_STALE | page | ETH price older than its max age. ERC20 collateral holders cannot refresh credit lines |
| ORACLE_MISMATCH | page | RelicPay points at an oracle other than the deployed one |
| OWNER_DRIFT | page | RelicPay owner differs from the expected address |
| GOVERNOR_DRIFT | page | RelicPay governor differs from the expected address |

ETH is the asset checked because ADR-009 makes every ERC20 holder's credit refresh depend on it. The keeper pushing prices (`ChainlinkPriceAdapter.pushAll`) should run well inside the ETH max age (300 seconds by default), and the warn threshold gives one missed cycle of notice.

## 7. Running it

```
npm run compile
npm run monitor:check                                    # catalog current, every event classified
node tools/monitor.js scan   --rpc $RPC_URL --deployments deployments/base-sepolia.txt --from 6000000 --min warn
node tools/monitor.js health --rpc $RPC_URL --deployments deployments/base-sepolia.txt
```

`scan` reads the key=value file DeployAll writes. With no `--from` it looks back 1000 blocks. The price deviation rule needs the previous price, so a scheduler that scans in windows should call `scan` from code and reuse one `memory` object, or overlap windows by one push. Both exit 1 when a page alert or finding exists and print JSON to stdout.

Suggested cadence once hosted: `health` every 5 minutes, `scan` every minute over the new blocks, the daily digest at a fixed hour from the warn alerts of the last 24 hours.

## 8. Response runbooks

Short, because the first move is the same: confirm the transaction on the explorer and decide whether it was intended.

Authority change (OwnershipTransferred, GovernorUpdated, OracleAuthorized, ActionAllowanceUpdated). Match the transaction to a change you made. If you did not, the owner key is compromised: pause nothing (there is no pause), revoke the governor with `setGovernor(0)` from the owner if the owner is still yours, and stop the keeper. Rotate keys before anything else.

PriceOracleUpdated or ORACLE_MISMATCH. Compare the new address to `deployments/`. If wrong, `setPriceOracle` back to the known oracle through the owner or governor.

Price deviation. Check the feed on the aggregator's own page. A real market move is expected; a push that does not match the aggregator is a compromised pusher, so deauthorize it with `deauthorizeOracle`.

ORACLE_STALE. Start the keeper, then run `pushAll`. Until a fresh price lands, ERC20 collateral holders cannot complete payments or be defaulted. ETH-only buyers are unaffected.

ProposalExecuted you did not expect, or a ProposalQueued you disagree with. Cancel during the delay if you can. After execution the path is a corrective proposal or an owner setter.

Large seller withdrawal. Usually a seller cashing out. Check the seller against the agreements that credited them; a balance larger than their credited agreements would indicate an accounting bug and should go straight to the audit contact.

## 9. Known gaps

- No pause. No contract in `contracts/` is Pausable, so RelicPay has no pause or circuit breaker and a page can only be answered by the revocation moves above. Whether to add one is an open design decision; raise it with the auditors (`docs/AUDIT_PREP.md`).
- ChainlinkPriceAdapter is not written by DeployAll, so `scan` and `health` only see it if its address is added to the deployments file as `CHAINLINK_ADAPTER=0x...`.
- Dashboard and extension health are out of scope. They hold no funds.
- Yield events are bookkeeping (ADR-010) and are deliberately info.

## 10. Owner decisions needed

1. Where it runs. A small always-on job (a VPS, a GitHub Actions cron, or a Cloud Run job) is enough; nothing here needs a database. Alternatively load `monitoring/alerts.json` into a hosted monitor such as Tenderly Alerts or OpenZeppelin Defender.
2. Where pages go. Push to a phone and email are the minimum; name the person on call.
3. Thresholds. Replace the two placeholder numbers after the pilot.
4. Who holds the keeper key, and how its balance is topped up.
