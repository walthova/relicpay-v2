# ADR-005: the extension shell's permission budget and where the confirmation comes from

Status: accepted, 2026-09-29
Context: roadmap "Browser extension revival, part c". ADR-003 decided what the extension may offer
and ADR-004 what a buyer-signed request is. This ADR decides what the shell around them is allowed
to ask the browser for, and how "the amount a buyer confirms is rendered by the extension, not by the
page" becomes a property the suite can check. Part c is split: c1 (this ADR) is the manifest and the
confirmation model, both data and both provable without a browser; c2 is the chrome.runtime wiring,
the injected surface and the popup UI.

## What v1 asked for

`<all_urls>` content script matching, `host_permissions` on `https://*/*`, plus `tabs` and
`scripting`. Together that reads every page the user visits and can inject into any of them, to
support a feature ADR-003 showed only functions on a seller's own storefront.

## Decision

**The manifest is generated from operator config and validated against a fixed budget.**
`extension/config.json` names three origin lists: seller storefronts, chain RPC endpoints, and
operator endpoints. `extension/lib/manifest.js` builds the manifest from them and refuses to return
anything `validateManifest` rejects. `extension/manifest.json` is generated by
`npm run extension:manifest`, and `npm run extension:check` plus a test prove the checked-in file is
exactly what the config produces, so a hand edit that widens it fails instead of shipping.

**The budget.**

- One API permission, `storage`, for the replay store. An MV3 service worker is terminated when idle,
  so an in-memory replay guard would forget every requestId between wakeups.
- Host permissions are exact https origins only: the sellers, the RPC, the operator. No wildcard
  scheme, no wildcard host, no path scoping beyond `/*`, no http. `optional_host_permissions` is
  refused because it lets the extension widen itself at runtime.
- One statically declared content script matching exactly the seller origins, not in all frames, not
  in the MAIN world, with no `match_about_blank` fallback. Each match must have a host permission.
- `tabs`, `scripting`, `activeTab` and others are refused by name so the reason is on record, and
  anything not on the allowlist is refused by omission.
- No `externally_connectable` (a page could message the service worker directly, skipping the
  content script boundary) and no `web_accessible_resources` (nothing is exposed to pages).
- Extension pages get a same-origin-only script CSP.

**The confirmation is derived from the signed message, never from the listing.**
`extension/lib/confirm.js` builds the popup's view from the `AgreementRequest` message, the exact
struct the wallet is about to sign. A view built from the listing could disagree with the signature
if a page changed what it said between quote and click. A view built from the signed struct cannot,
because they are the same bytes. Amounts are formatted from BigInt with no float and no rounding.
The credit unit (symbol, decimals) comes from operator config, since a page that could name the unit
could print "USD" over a raw 18-decimal amount.

The quote is optional context for warnings and the unconfirmed flag, and is cross-checked against the
message on buyer, total, count, interval and grace. A disagreement throws instead of picking a side.
A `canSign` flag goes false once the request has expired, so the popup cannot offer a signature the
operator will refuse.

## Why

The tabs and scripting reductions follow directly from ADR-003: with a seller-scoped content script
and the tab id taken from the message sender, neither permission has a use. Making the manifest
generated and checked, rather than merely reviewed, is the same move ADR-001's abi:check made for
ABIs: the invariant is enforced where the artifact is produced.

## Consequences and what c2 still owes

- Host and origin values in `extension/config.json` are placeholders for the pilot (position.gallery,
  the Sepolia public RPC, an operator endpoint). Set the real ones before loading the extension.
- An open decision for c2: a popup has no injected `window.ethereum`. Signing `eth_signTypedData_v4`
  has to be relayed to a page-side provider, which means crossing back into the page world. That
  crossing must carry only the already-built typed data and return only a signature, and must be
  designed with the same distrust of the page as everything else. This ADR deliberately does not
  pre-decide it.
- c2 also owes the chrome.runtime wiring of extension/lib/messages.js, the injected surface (a
  closed shadow root showing the quote, never the confirmation), and the popup rendering
  `buildConfirmation`'s output.
