**Bug caught by the test suite itself, then fixed:** the original fallback
design claimed a failed CPI could be caught mid-transaction (`match
try_kamino_deposit(...) { Err(_) => emit fallback, return Ok(()) }`). A
real test (pause the mock reserve, call `kamino_probe_deposit`) proved this
false — the mock's `ReservePaused` error surfaced as the top-level tx
failure regardless. Solana has no try/catch across a CPI boundary once
`invoke_signed` actually executes the target. Reworked to a preflight
guard (read `reserve.paused` from raw account data *before* invoking; skip
the CPI and emit `...Fallback` only when predictable) and corrected the
claims in `kamino_cpi.rs`, `kamino_probe.rs`, and
`docs/design/KAMINO_CPI_INTEGRATION.md`. Flagged the honest limits: this
preflight is mock-specific/fragile and only catches *predictable* failures;
the architecturally correct fix (crank-based deposits off the purchase's
critical path) is documented but deferred, not implemented.
