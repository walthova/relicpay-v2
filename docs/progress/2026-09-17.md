# Relic Pay Build — 2026-09-17

**Shipped**: `cancel_agreement_reconciled`, the buyer-side counterpart to
2026-09-14's `merchant_withdraw_reconciled`. `cancel_agreement` only reads
`escrow_usdc` directly, so a buyer whose escrow was partially cranked into
Kamino (`kamino_probe_deposit`) would under-count the true balance on
cancellation; `kamino_probe_redeem` already permits `Active` state, so a
two-transaction workaround existed, but no single-transaction path did.
This closes that UX gap: redeems the *entire* `escrow_kamino_collateral`
balance inline (a full close-out, unlike the merchant path's "just enough"
shortfall redemption), then runs the existing 10%-fee/90%-refund split
against the reconciled balance — one transaction, no separate crank.
Purely additive: `cancel_agreement` untouched.

**Files**: `programs/relicpay/src/instructions/cancel_agreement_reconciled.rs`
(new), `instructions/mod.rs`, `lib.rs`, `tests/v2-features.ts` (2 new cases:
full-reconcile-then-cancel with correct fee/refund split; degrade to plain
cancel_agreement behavior when Kamino was never touched).

frozen characterization suite untouched and passing, all v2 features
